# 陪跑展示腳本（10 分鐘客戶實測）

> 目的：讓客戶用**自己的產品**（3 張照片＋5 句介紹）在 10 分鐘內拿到影片與文案，
> 並觀察他最後把哪種輸出帶走（統計會自動記在 設定 → 匯出行為統計）。

## 事前檢查（客戶到場前 10 分鐘）

- [ ] `pnpm dev` 已啟動（http://localhost:3410）
- [ ] `pnpm worker` 已啟動且 log 出現「就緒，開始輪詢」（首次啟動要下載 113MB Chrome，**務必提前**）
- [ ] `.env` 的 `TTS_PROVIDER=edge`（真中文語音）；當場斷網也不會炸，會自動退回 mock 音軌
- [ ] `.env` 的 `AI_PROVIDER=mock`——**陪跑當下不要開真 AI**。mock 生成約 2 秒，
      `anthropic` 要 90–170 秒，客戶會盯著轉圈圈看三分鐘。真 AI 留給事後正式產出
      （改成 `AI_PROVIDER=anthropic` 即可，金鑰與模型已設好），文案品質確實較好。
- [ ] 開好 `/demo` 確認森日茶研範例正常 —— 這是渲染等待時的備用展示
- [ ] 跟客戶要素材：**3 張產品照（JPG/PNG）＋5 句話介紹＋3–5 個賣點＋一句 CTA**（可以事前用 LINE 收）

## 現場流程（含講稿提示）

| 時間 | 操作 | 說什麼 |
|---|---|---|
| 0:00–1:30 | `/brands/new` 填品牌：名稱、產業、客群、語氣、CTA、**用取色器抓他品牌色** | 「先把你的品牌記住——之後每支影片自動用你的顏色和語氣。」 |
| 1:30–3:30 | `/projects/new` 填產品：貼上 5 句介紹、逐條填賣點、選風格與長度 | 「AI 只會用你給的事實，不會瞎編功能。」 |
| 3:30–4:30 | 專案頁上傳 3 張照片 → 按「生成企劃與腳本」 | 生成約 2 秒。「一次拿到 90 秒主影片＋3 支短影音＋四個平台的貼文。」 |
| 4:30–6:00 | 策略頁走一遍：一句話策略、痛點、社群文案（示範一鍵複製） | 觀察他對哪一塊有反應——文案還是影片。 |
| 6:00–7:30 | 編輯器：點一個場景改旁白 → 預覽即時變 → 示範「重新生成此場景」 | 「不滿意就改，改的只有這一格，其他不動。」 |
| 7:30 | 渲染頁按「渲染 MP4」（主影片） | 「90 秒的片大約渲 3–4 分鐘，我們先看短影音腳本。」 |
| 7:30–11:00 | 等待時：看短影音腳本、問付費問題（見下） | 進度條在渲染頁會自己動。 |
| 11:00– | 播放 MP4、下載給他（＋SRT＋文案） | **讓他自己按下載**——下載行為就是付費訊號。 |

## 等待渲染時要問的三個問題

1. 「這四種輸出（影片／短影音／貼文文案／字幕），哪一個你**明天就會拿去用**？」
2. 「如果一個月固定產出這些，你願意付多少？」（不給選項，聽他先開）
3. 「今天缺了什麼，讓你不敢直接發出去？」（收集模板方向的證據）

## 異常應對

- **渲染超過 5 分鐘沒動**：看 worker 終端機；job 失敗會顯示在渲染頁。備案＝播森日茶研預渲染的 MP4。
- **Edge TTS 掛了**（非官方端點）：worker 會自動退 mock 音軌繼續渲；跟客戶說「正式版接商用語音」。
- **客戶照片超過 10MB**：先用手機截圖縮小再傳。

## 事後 5 分鐘

- 設定頁截圖「匯出行為統計」，記到客戶筆記。
- 把專案 JSON 匯出存檔（客戶素材與腳本都在裡面）。
